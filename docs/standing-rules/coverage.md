# Покрытие исходных требований

Источник — 28 уникальных полных пользовательских сообщений предоставленной сессии, сверенных с сохранёнными копиями и исходной длиной записей. Номера U01–U28 обозначают порядок сообщений. Приватный транскрипт, идентификаторы сессии и пользовательские пути не публикуются. Предложения и пересказы ассистента не являются требованиями.

Текущее поручение объединяет совместимые требования в одну задачу и разрешает реализацию и push. Исторические «только предложи», «пока не делай» и остановка конкретного критика определяли тот момент разговора; действующее поручение разрешает выполнение. Их общий смысл — соблюдать фактический режим — сохранён в01/17/68. Экспорт исходной сессии был историческим действием, не поручением разрабатывать exporter в этом репозитории.

## Разрешённые противоречия и границы

- Durable task меняется по смыслу. Ранее «сделай ещё Y» автоматически исключалось из обновления; теперь новое требование Y сохраняется, локальная перестановка действий не навязывает update.
- Реальная snapshot schema `task` использует `agent_name` и `run_in_background`; прежняя инструкция `Agent/subagent_type` не подходит mcode. Точные именованные роли и их payload остаются обязательными там, где workflow их требует.
- Старое advertised описание layout-audit с тремя ширинами не уменьшает требование пяти. Описание skill не заменяет чтение его текущей инструкции и разрешение конфликта по иерархии.
- `remind.on_user_end` и `_distribution.json` не исполнялись engine. Активные интервалы заданы в поддерживаемом `every_n_tools`; `every_input` — отдельное событие. Инертный distribution-файл удалён из поставки.
- Все14 rules применимы к ролям и восстанавливаются при lifecycle boundaries. Старое исключение `intent-auditor` снято: такой роли нет среди24 поставляемых, а инструкции сохранять пользовательский смысл применимы ко всем. Leaf-review условие80 предотвращает рекурсию без отключения исходных принципов.
- Review outside task-skill обязателен владельцу поставки. Task-cycle уже содержит этот gate; worker/leaf-review не создают новую цепочку критиков. Недоступная installed role обозначается как native gate blocker, не как выполненная проверка.
- Пять выбранных ширин, интервалы остальных reminders и разбиение на14 правил — инженерные решения этой поставки, не якобы дословные числа пользователя. Пользователь явно задал число проверок5, каденции2/5 и смешение остальных.
- Абсолютный запрет Grid/max-width/дизайн-пустот, обязательный numeric ledger, формула допуска1–2px, обязательное эхо требования, универсальная новая пауза на согласование и повторная инвентаризация каждой простой задачи не вводятся.
- Обязательный implementation review получил исполнимый standalone вход `TASK` с нейтральным поручением, источниками и scope. Пять task-ролей проверяют структуру входных артефактов доступными read/search/bash; отсутствующий `task_artifact_check` не является обязательной зависимостью. Противоречия exact payload, формата verdict и маршрутизации согласованы с task-skill. Read-only права не означают положительный verdict дефектного результата.
- Полный каталог — snapshot объявленных возможностей. Поставка не устанавливает остальные72 skills и внешние MCP, не доказывает все116 вызовов и не обещает гарантированного поведения модели. Hook delivery, native host integration, действительный role dispatch и пользовательская установка — разные свойства.

## Проверяемые свойства поставки

Реальные declared hooks проверяются в изолированной среде: полные тела при startup/resume/compact/child start; input отдельно от completed-tool counter; полный70 через2, goal/model71 через5; ошибки исполнения, concurrent sessions и сохранение original result. Native host probe дополнительно исполняет опубликованный parser/runner/lifecycle0.6.12 с Bun1.4.3, без обращения к модели.

Upgrade выполняется из README в disposable HOME, с backup, docs,14 rules и сохранением unrelated config/runtime/user rules. Очистка исторических отвергнутых файлов допускается только при совпадении точного известного SHA-256; изменённые одноимённые файлы и symlinks остаются для ручной сверки. Изолированная проверка установки не означает установку на пользовательской машине.
